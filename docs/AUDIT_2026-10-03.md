## 5. Lock and PIN code

- `lib/lock/*`. Secure storage keys `lingkaran.lock.v1.*`: profile id, display name, masked email, PIN hash, failed count, wait-until, biometric flag.
- Bug cause confirmed: `signOutTo` calls `LockService.clear()` which deletes the PIN hash. `app_entry.dart` `_unlock` calls `clear()` on ANY error, including a plain network error. `test/lock/sign_out_test.dart` asserts storage is empty after sign out.
- `LockService.remember()` already drops the PIN when a different profile id is remembered.
- The lock is disabled on web (memory store), unless `WEB_LOCK_TEST`.

## 6. Marketplace

- Tables: `marketplace_listings` (status pending, approved, rejected, sold; seller_id; contact_info max 300), `marketplace_reports` (one per reporter and listing; reasons spam, prohibited, misleading, other), `marketplace_admins` (profile_id, created_at, key_hash). Bucket `marketplace` (public, images, 2 MB).
- Writes only through SECURITY DEFINER functions: `marketplace_create_listing`, `_update_listing`, `_set_sold`, `_delete_listing`, `_my_listings`, `_admin_pending`, `_review_listing`, `_report_counts`, `marketplace_is_admin`.
- Reads: policy `status = 'approved'` for direct select.
- Seeds: `seed_marketplace.sql` (12 listings, 1 admin).
- Admin screen: `marketplace_admin_screen.dart` (asks for a passphrase first).
- Two copies of each marketplace migration: `20260930052418/052438/052502/052511` and `20260930090000/090100/090200/090300`. I diffed all four pairs: **they are byte identical** (only the timestamp differs). The second copy is the idempotent duplicate, safe either way.

## 7. Shared admin passphrase

- Stored as a bcrypt hash in `marketplace_admins.key_hash` (set with `marketplace_set_admin_key`, owner only).
- Checked by `marketplace_admin_authorized(profile, key)`, used by `marketplace_admin_pending`, `marketplace_review_listing`, `marketplace_report_counts` (the `p_key` argument). Every refusal sleeps 1 second.
- App: `marketplace_repository.dart` passes `adminKey`; `marketplace_admin_screen.dart` asks for it. Test: `test/security_fixes/admin_passphrase_test.dart`.

## 8. Notifications

- Table `notifications`: id, recipient_id, job_post_id, title, body, read_at, created_at. After the hardening migration: no insert for anon, update only `read_at`.
- Only writer today: trigger `notify_poster_on_application()` (on `job_applications` insert). It also writes `email_log` (recipient email, subject, body).
- App reads: `notifications_screen.dart` (list, mark read, opens the job), unread count in `job_board_screen.dart`. There is no bell on Home.

## 9. Personal data stored

`alumni_profiles` columns: id, user_id (always null, no real auth), nim, name, faculty, major, graduation_year, current_employer, current_role, industry, company, verification_status, subscription_status, created_at, updated_at, email (unique, not null), city. RLS: select open to everyone (so email and NIM reach every client; this is known and stays a documented gap). Update is open but a trigger locks identity columns for anon.

Other personal data:
- `job_applications`: full_name, email, phone, linkedin_url, portfolio_url, cover_note, cv_path.
- Bucket `cvs`: CV files, public by URL, 5 MB, pdf/doc/docx.
- Bucket `marketplace`: product photos, public by URL.
- `messages`, `conversations`, `city_chat_messages`: chat text (hidden in this work, data kept).
- `email_log`: recipient email and message text.
- `marketplace_listings`: contact_info (free text), shop_url, city.
- On the device only: PIN hash, remembered profile id, display name, masked email, biometric flag (flutter_secure_storage).
- No analytics, no location (the "nearby" feature uses the seeded city field and a fixed distance table).

## 10. Nearby alumni map and theme

- There is NO map package. `lib/widgets/nearby_map_view.dart` hand-paints the map with `CustomPaint` (colors are fixed: land `0xFFE8E2D4`, water `0xFFAFD8E8`). Markers are widgets.
- The app has NO dark theme: `main.dart` sets only `theme: AppTheme.light()`, no `darkTheme`. So Stage 7C makes only the map follow the system brightness.

They exist. So "someone applied to my job" notifications already exist and will move to the new notification system.

## 12. Where errors are shown and how

`lib/util/friendly_error.dart`: `friendlyError(e)` and `friendlyLoadError(thing, e)` map any error to a safe sentence (never shows raw text).

Load error screens (text with Try again): directory, nearby, job board, applicants, notifications, announcements, messages list, email log.
Failed form submits (inline `_error`): verification, post job, apply job, subscribe (to be removed).
Snackbars with an error: city chat, chat, profile detail (start chat), marketplace form, my listings, marketplace detail (link and profile errors), marketplace admin toast, nearby (WhatsApp), safe link chip.
Dialogs: `marketplace_gate.dart` (removed with subscription), my listings (delete confirm), admin (reject reason).
Marketplace errors are mapped by `marketplace_messages.dart`.

## 13. Navigation

`home_shell.dart`: 4 tabs (Home, Directory, Chat, Profile) in an `IndexedStack`, back from another tab goes to Home. Home tiles open Jobs, Marketplace, Directory, Nearby. News opens from the banner area. The Profile tab is `profile_detail_screen.dart` with the current user.
